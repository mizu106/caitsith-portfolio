# 「非機能要求」って何？システム開発の”見えない品質”を支える大切な考え方

### 導入：システムの「使いやすさ」を支えるもの

私たちが普段使っているWebサイトやアプリ。その使い心地の良し悪しは、何で決まるのでしょうか。「ボタンを押したらすぐに画面が変わる」「安心して個人情報を入力できる」「いつでも安定して使える」。こうした当たり前とも思える快適さは、実は偶然生まれるものではありません。

システム開発というと、目に見える「機能」を作ることばかりに目が行きがちです。なぜなら、それらが仕様書で最も具体的に記述され、ユーザーが直接触れる部分だからです。しかし、本当に優れたシステムは、その裏側にある”見えない品質”によって支えられています。この記事では、その”見えない品質”の正体である**「非機能要求」**について、基本からやさしく解説していきます。

--------------------------------------------------------------------------------

## 1. システムの要求には2種類ある：「機能要求」と「非機能要求」

システム開発を進める上で、発注者と開発者が「どんなシステムを作るか」を合意するためにまとめるものを「要求」と呼びます。この「要求」には、大きく分けて2つの種類があります。

### 1-1. 「機能要求」とは？ ― システムが「何をするか」

「機能要求」とは、そのシステムがユーザーのために**「何ができるか」**を定めたものです。いわば、システムの中心的な役割や目的そのものを指します。

- **ECサイトの例**
    - ユーザーとして会員登録ができる
    - キーワードで商品を検索できる
    - 商品をショッピングカートに入れて決済ができる

このように、ユーザーが直接操作して目的を達成するための具体的な機能が「機能要求」にあたります。

### 1-2. 「非機能要求」とは？ ― システムが「どのように動くか」

一方、「非機能要求」とは、機能要求をどのような品質で実現するか、つまり**「どのように動くか」**を定めるものです。これはシステムの性能や使い勝手、安全性など、目には見えにくいけれどシステムの価値を大きく左右する要素です。システムの”性格”や”体力”を決めると考えると分かりやすいかもしれません。

- **ECサイトの例**
    - 検索ボタンを押してから**3秒以内**に結果を表示する（**性能**）
    - スマートフォンでも見やすい画面デザインにする（**使いやすさ**）
    - クレジットカード情報は暗号化して安全に管理する（**セキュリティ**）

機能要求が「できること」を定義するのに対し、非機能要求は「その機能を、どれだけ快適に、安全に、安定して提供できるか」を定義します。

### 1-3. 2つの要求の違いが一目でわかる比較表

`機能要求`と`非機能要求`の違いを、ECサイトを例に表で比較してみましょう。

|   |   |   |
|---|---|---|
|項目|機能要求|非機能要求|
|**目的**|システムが**「何をするか」**を定義する|システムが**「どのように動くか」**を定義する|
|**具体例****（ECサイトの場合）**|* 商品を検索できる<br>* レビューを投稿できる<br>* 購入履歴を確認できる|* 検索結果は常に3秒以内に表示される<br>* 24時間365日いつでもサービスを利用できる<br>* 不正アクセスから個人情報を守れる|
|**着眼点**|ユーザーが直接触れる「機能」そのもの|システムの「品質」や「制約」に関するもの|

では、なぜこの「どのように」を決める非機能要求が、システム開発でこれほどまでに重要なのでしょうか。

## 2. なぜ非機能要求は重要なのか？

「非機能要求は、単なるいちゃもん（nitpicking）ではないか？」と感じる人もいるかもしれません。なぜなら、目に見える機能と違い、「万が一」の備えや「感覚的」な品質といった、まだ起きていない問題や抽象的な目標を扱うことが多いからです。しかし、非機能要求はシステムの成功に不可欠な要素であり、これを軽視すると大きな問題につながります。

### 2-1. 非機能要求が足りないと起こる悲劇

もし、システム開発の初期段階で非機能要求を十分に検討しなかったら、どのようなことが起こるでしょうか。

- **悲劇①：サイトが重くて、誰も使ってくれない**
    - **シナリオ**：セール初日にアクセスが集中し、サイトが全く開かなくなった。やっと開いてもページの表示に10秒以上かかり、多くのユーザーが買い物を諦めて離脱してしまった。
    - **ビジネスへの影響**：売上の機会損失、ブランドイメージの低下。
    - これは、アクセス集中時の処理速度といった**「性能」**に関する非機能要求の検討が不十分だったために起こる典型的な例です。
- **悲劇②：個人情報が漏洩し、信頼を失う**
    - **シナリオ**：システムのセキュリティに脆弱性があり、悪意のある第三者によって顧客の氏名や住所、クレジットカード情報が盗まれてしまった。
    - **ビジネスへの影響**：顧客からの信頼失墜、損害賠償、事業停止のリスク。
    - これは、不正アクセス対策やデータ暗号化といった**「セキュリティ」**の非機能要求が軽視された結果です。
- **悲劇③：システムが頻繁に止まり、仕事にならない**
    - **シナリオ**：社内業務で使うシステムが、月末の忙しい時期に頻繁に停止してしまう。そのたびに業務が中断し、大きな手戻りが発生する。
    - **ビジネスへの影響**：生産性の低下、従業員のストレス増大。
    - これは、障害発生時の復旧時間やシステムの稼働率といった**「可用性」**や**「信頼性」**の非機能要求が定義されていなかったために起こります。

これらの悲劇はすべて、非機能要求の検討不足が原因で起こり得ます。

### 2-2. "良いシステム"を作るための土台

非機能要求は、ユーザーが快適にサービスを使い続け、企業が安心してシステムを運用するための**「土台」**です。いくら画期的な機能（機能要求）をたくさん作っても、その土台が脆弱であれば、システムはすぐに使えないものになってしまいます。

特に、システムの**「安定した運用設計」**という観点から、非機能要求は極めて重要です。システムが将来にわたって安定して稼働し続けるためには、性能、信頼性、セキュリティといった非機能要求をあらかじめ明確に定義しておく必要があるのです。

このように重要な非機能要求を、私たちはどのように整理し、開発チームと共有すれば良いのでしょうか。そのための強力なツールが存在します。

## 3. 非機能要求を整理する道具：「非機能要求グレード」

非機能要求は多岐にわたるため、抜け漏れなく検討するのは簡単ではありません。そこで役立つのが、IPA（情報処理推進機構）が提供している**「非機能要求グレード」**です。

### 3-1. 「非機能要求グレード」とは？

「非機能要求グレード」とは、IPAが提供する、**曖昧になりがちなシステムの品質要求を、具体的で測定可能な項目に落とし込むためのツールです。**特に、システム開発の**「上流工程」**と呼ばれる初期段階で、発注者と開発者が非機能要求について共通の認識を持つために活用されます。

このツールの最大の特徴は、その名の通り「グレード（等級）」という考え方を取り入れている点にあります。これは、すべてのシステムに同じ品質を求めるのではなく、**そのシステムが社会やビジネスに与える影響度に応じて、必要な品質レベルを段階的に設定しよう**というアプローチです。

例えば、社内向けの簡単なブログシステムと、大規模なネット銀行のシステムでは、求められるセキュリティや性能の「グレード」が全く異なります。ホテルに星のランクがあるように、システムにも適切な品質ランクを設定することで、過剰な投資や品質不足を防ぎ、合理的な開発目標を立てることができるのです。

### 3-2. 6つの大分類で品質を考える

「非機能要求グレード」は、システムの品質に関する要求を**6つの大きなカテゴリ**に分類して整理する枠組みを提供しています。

これにより、開発者は「可用性（いつでも使えるか）」「性能（速く動くか）」「セキュリティ（安全か）」といった様々な観点から、網羅的に品質要件を洗い出すことができます。これは、**漠然とした「良いシステムを作りたい」という目標を、「測定可能な品質項目のチェックリスト」へと変換する**強力なアプローチであり、計画段階で重要な品質特性が見過ごされるのを防ぎます。

この記事で非機能要求の基本を掴んだら、次の一歩を踏み出してみましょう。

## 4. まとめと次のステップ

この記事では、「非機能要求」の基本的な考え方とその重要性について解説しました。最も重要なポイントを3つにまとめます。

1. **機能要求と非機能要求の違い**
    - 「機能要求」はシステムが**「何をするか」**を定めるのに対し、「非機能要求」は**「どのように動くか」**という品質を定めます。
2. **非機能要求がシステムの品質と成功に不可欠である理由**
    - 非機能要求は、システムの性能、安全性、安定運用を支える土台です。これを疎かにすると、ユーザー離れや情報漏洩といった深刻な問題を引き起こす可能性があります。
3. **非機能要求を整理するためのツール「非機能要求グレード」の存在**
    - IPAが提供する「非機能要求グレード」は、多岐にわたる非機能要求を体系的に整理し、システムの重要度に応じた適切な品質目標を設定するための強力なツールです。

「非機能要求」は、システム開発の成功を陰で支える、非常に奥が深いテーマです。さらに詳しく学びたい方は、IPAの公式ページはもちろんのこと、GPTech社やSint社といった実務者が詳細に解説しているブログ記事も、非常に優れた情報源となります。品質の高いシステム作りのための第一歩として、ぜひ探求を続けてみてください。
