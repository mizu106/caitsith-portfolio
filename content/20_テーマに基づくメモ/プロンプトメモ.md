資料作成用プロンプト：MDI導入に伴うイベントログ出力への影響と評価

この資料の目的は、MDIの検知能力を最大化するために必要な監査設定が、ローカルサーバーのログ出力量に与える影響を定量的に示し、運用の安全性を示すことです。

スライド1：タイトルと概要
• **タイトル：** Microsoft Defender for Identity (MDI) 導入に伴う監査ポリシー設定とログへの影響について
• **概要：** MDI導入に必要な監査設定の目的と、本資料で説明するイベントログ増加量、ストレージ容量への影響評価の全体像を提示する。
• **テキスト概要：**
    ◦ MDIはActive Directoryのシグナルを監視し、高度な脅威を特定するソリューションである12。
    ◦ 脅威検知のカバレッジを確保するため、特定のWindowsイベント（NTLM認証、機密グループの変更、サービス作成等）の収集が不可欠である3...。
    ◦ 本資料では、監査設定の結果として発生するログ増加量と、システムへの影響をデータに基づき評価する。

スライド2：MDIで必要な監査ポリシーとオブジェクトの監査
• **タイトル：** MDIを支える監査構成の要件
• **概要：** MDIセンサーが脅威を検知するために必要とする「高度な監査ポリシー」と「ドメインオブジェクトの監査」の具体的な構成を説明する。
• **テキスト概要：**
    ◦ **高度な監査ポリシー：** 資格情報の検証(4776)、アカウント管理(4726等)、DSアクセスの変更(5136)などの成功/失敗イベントを記録する必要がある6。
    ◦ **ドメインオブジェクトの監査：** ユーザーやグループの変更を捉えるため、Active Directory内のオブジェクトに対する書き込み監査を構成する78。
    ◦ **NTLM監査：** Windowsイベント8004を収集し、NTLM認証アクティビティを可視化する39。
    ◦ **センサーの役割：** センサーはこれらのログをローカルで読み取り、解析された情報のみをクラウドサービスへ転送する1011。

スライド3：データに基づくイベントログ増加量の見積もり
• **タイトル：** イベントログ出力量の増加に関する定量的評価
• **概要：** 指定されたデータに基づき、Active Directoryにおけるログ増加の具体的な数値を示す。
• **テキスト概要：**
    ◦ **増加指標：** Active Directoryにおいて最も増加量が多いケースで、**5,000ユーザーあたり約400MB**の増加が見込まれる。
    ◦ **現行のログサイズ設定：**
        ▪ Application、セキュリティ、システムの各ログ保存サイズ：デフォルト（各20,480KB = 約20MB）。
    ◦ **評価：** 監査の有効化により、ログの生成速度が上がるため、デフォルトの20MB枠ではログの回転（上書き）サイクルが従来より早くなる。

スライド4：ディスク容量とローカルストレージへの影響評価
• **タイトル：** ローカルディスクへの影響と安全性の評価
• **概要：** Azureデフォルトのディスク仕様に基づき、空き容量への影響が軽微であることを示す。
• **テキスト概要：**
    ◦ **サーバー仕様：** AzureデフォルトのOSディスク容量 128GB。
    ◦ **現状：** 約50GBの空き容量を確保。
    ◦ **増加量に対する評価：**
        ▪ MDIセンサー自体が必要とするディスク領域は最小6GB、推奨10GB（バイナリとログを含む）である12。
        ▪ 監査によるログ増加分（400MB/5000ユーザー）を考慮しても、50GBの空き容量に対して占有率は極めて低く、ディスクの枯渇リスクは無視できるレベルである。

スライド5：ログの収集フローとローカル運用の仕様
• **タイトル：** ログ収集アーキテクチャと運用仕様の維持
• **概要：** 収集されたログがXDRに集約されることと、ローカルログ設定は現行踏襲することを明示する。
• **テキスト概要：**
    ◦ **XDRへの集約：** MDIセンサーによって収集・解析されたログデータは、Microsoft Defender XDRに取り込まれ、30日間の生データ保持と高度なハンティングに利用可能となる1314。
    ◦ **ローカルログ運用の維持：**
        ▪ ローカルに残すイベントログ（Application/セキュリティ/システム）は、システム構築時の仕様（デフォルトサイズ等）を維持する。
        ▪ MDIは全アクティビティを保存する「監査ソリューション」ではなく、検知に必要なデータのみをキャプチャする設計であるため、ローカル側のログ設定を大幅に変更する必要はない15。

スライド6：結論
• **タイトル：** 評価結果のまとめ
• **概要：** 監査設定によるセキュリティ向上と、リソースへの影響のバランスについて結論を述べる。
• **テキスト概要：**
    ◦ **セキュリティの最大化：** 監査ポリシーとオブジェクト監査の設定により、高度な攻撃に対する検知能力が確立される。
    ◦ **リソース影響：** ログ増加量はディスク容量に対して軽微であり、システムの安定稼働に支障はない。
    ◦ **運用：** ローカルログの仕様は変更せず、MDIを介してXDR側で高度な分析と長期的な可視化（30日間〜）を実現する。

4. **評価の実施：** 最後に、リスク（ログの回転が早くなる可能性）とベネフィット（脅威検知の実現）を比較し、今回のシステム仕様における妥当性を承認する形式でまとめます。

### AADCのディスク使用量調査
AADC主と復でディスク使用量に50GBの差があったことを調査する為の方針作成プロンプト

#### プロンプト１：手書きプロンプト

```
AzureActive DirectoryConnectサーバーのディスクを圧迫する要因を、影響度が大きい方から10件列挙する
```

##### 出力
Azure Active Directory Connect（現在の名称：Microsoft Entra Connect）サーバーのディスクを圧迫する主な要因を、**一般的な環境における影響度が大きい順**に10件列挙します。構成（Express / Custom、Staging有無、SQL種別など）によって多少前後しますが、実務上よく問題になる順序です。

###### 1. 同期ログ・トレースログの肥大化
**影響度：非常に大**
- 保存先例：
    - `C:\ProgramData\AADConnect\`
    - `C:\ProgramData\Microsoft\Azure AD Connect\`
- 内容：
    - 同期処理ログ
    - エラーログ
    - トレースログ
- 原因：
    - エラー多発
    - トラブルシューティング目的で詳細ログを有効化したまま
    - ログローテーション未設定

###### 2. [[SQL Server]]（LocalDB / SQL Express / Full SQL）のデータベース肥大化
**影響度：非常に大**
Azure AD Connectは内部でSQL DBを使用します。
- DB名例：
    - `ADSync`
- 保存先例：
    - `C:\Program Files\Microsoft SQL Server\`
- 肥大化要因：
    - オブジェクト数が多い
    - 同期履歴の蓄積
    - メタデータの増大
    - クリーンアップ未実施

###### 3. 同期履歴（Metaverse / Connector Space）の蓄積
**影響度：大**
- 内容：
    - オブジェクト変更履歴
    - インポート／エクスポート履歴
- GUI上では見えにくいが、DB上では大きくなる
- 長期間メンテナンスしていない環境で肥大化しやすい

###### 4. Windowsイベントログの肥大化
**影響度：大**
- 対象ログ：
    - Application
    - System
    - Directory Synchronization関連ログ
- 同期エラーが頻発していると急増
- ログ上限未設定 or 大きく設定されているとディスク圧迫

###### 5. Windows Update関連の一時ファイル・キャッシュ
**影響度：中〜大**
- 例：
    - `C:\Windows\SoftwareDistribution`
    - `C:\Windows\WinSxS`
- Azure AD Connectサーバーは放置されがちで、更新ファイルが溜まりやすい

###### 6. Azure AD Connectアップグレード時のバックアップファイル
**影響度：中**
- 自動アップグレード時に旧バージョンの構成やバイナリが残る場合あり
- 保存先：
    - `C:\Program Files\Microsoft Azure AD Sync\`
    - `C:\ProgramData\AADConnect\`

###### 7. SQL Serverログファイル（トランザクションログ）の肥大化
**影響度：中**
- `.ldf` ファイル
- フルリカバリモデルの場合、バックアップ未実施で肥大化
- Express/LocalDBでも蓄積するケースあり

###### 8. デバッグ・サポート用ダンプファイル
**影響度：中**
- 障害発生時に自動生成されることがある
- 拡張子例：
    - `.dmp`
- 数GB単位になることも

###### 9. 一時ファイル（Tempフォルダ）
**影響度：小〜中**
- 場所：
    - `C:\Windows\Temp`
    - `%TEMP%`
- 同期処理・更新処理・MSI実行時の残骸

###### 10. ウイルス対策ソフト・EDRのログ／キャッシュ
**影響度：小〜中**
- Defender, SentinelOne, CrowdStrikeなど
- ログローテーション設定が甘いと増え続ける

---
### 実務的に最優先で確認すべきポイント
ディスク逼迫時は、以下の順で確認すると効率的です。
1. ログディレクトリのサイズ
2. SQL DBファイル（.mdf / .ldf）
3. イベントログサイズ
4. SoftwareDistribution / WinSxS
5. Dumpファイル

---
必要であれば、
- ディスク使用状況の調査手順（PowerShell付き）
- 安全な削除対象一覧
- SQL DBの肥大化対策
- ログローテーション設定方法
- Azure AD Connect向けの容量設計目安
まで具体的にまとめます。
