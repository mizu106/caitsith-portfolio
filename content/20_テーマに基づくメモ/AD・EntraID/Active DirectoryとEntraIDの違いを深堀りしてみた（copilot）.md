## グループの違い
Azure AD Connect（現Entra Connect）を使うとオンプレADのセキュリティグループをEntraIDに同期できる。但し、同期後のセキュリティグループは編集不可になる。

### EntraIDで使用するグループの種類
| グループの種類                | 主な用途                                 | 特徴                                |
| ---------------------- | ------------------------------------ | --------------------------------- |
| **セキュリティグループ**         | アクセス制御（例：アプリやリソースへのアクセス）             | ロール割り当てや条件付きアクセスに使える。メール機能はなし。    |
| **Microsoft 365 グループ** | コラボレーション（例：Teams、Outlook、SharePoint） | メールボックス、カレンダー、Plannerなどが自動で付いてくる。 |

### オンプレADのグループの種類
| グループの種類        | 説明                        |
| -------------- | ------------------------- |
| **セキュリティグループ** | アクセス制御に使う（ファイル共有、GPOなど）   |
| **配布グループ**     | メール配信リストとして使用（Exchangeなど） |

### オンプレADとEntraIDのグループの違い

| 項目         | オンプレミスADのグループ                 | Entra IDのグループ                                      |
| ---------- | ----------------------------- | -------------------------------------------------- |
| **存在場所**   | オンプレミスのドメインコントローラー            | Microsoft Entra ID（クラウド）                           |
| **同期**     | Entra Connectで同期可能（ただし一方向）    | 同期されたグループは読み取り専用                                   |
| **種類**     | セキュリティグループ、配布グループ             | セキュリティグループ、Microsoft 365グループ                       |
| **用途**     | ファイル共有、GPO、オンプレミスアプリのアクセス制御など | クラウドアプリ（Teams、SharePoint、Intuneなど）のアクセス制御やコラボレーション |
| **動的グループ** | なし（スクリプトなどで実現）                | 属性ベースで自動管理可能（Dynamic Group）                        |

#### 1. **同期できるグループの種類**
- **セキュリティグループ**：同期可能（最も一般的）
- **配布グループ**：同期可能だが、Exchange Onlineで使うには**メール有効化**が必要  
- **動的配布グループ**：**同期不可**（Exchangeオンプレの機能で、クラウドに対応していない）

### 2. **同期後の編集制限**
- オンプレADから同期されたグループは、**Entra ID上では読み取り専用**。
- つまり、**メンバーの追加・削除、グループ名の変更などはオンプレ側でしかできない**。
- Entra ID上で編集したい場合は、**クラウドネイティブなグループを別途作成**する必要がある。

### 3. **メンバーシップの制限**
- グループのメンバーとして同期できるのは：
    - ユーザー
    - 他のグループ（ネストされたグループ）※ただし、**ネストの深さに制限あり**
- **グループのネストはEntra IDでは10階層まで**がサポートされているけど、オンプレADからの同期では**制限が厳しくなることもある**。

### 4. **同期対象のフィルタリング**
- Entra Connectでは、OUや属性ベースで**同期対象のグループを制限**できる。
- ただし、**同期対象外にしたグループはEntra IDから削除される**ので注意。

## OUの扱い
オンプレADにはOUという概念があり、アカウント、デバイス、OUを入れられるコンテナとして機能するが、EntraIDには無いので同期不可となります。
しかしEntra ConnectでEntraIDに同期する際に、同期するオブジェクトをフィルタリングする単位として利用可能です。

EntraIDでOUのようなことをするには、セキュリティグループのネストが１０階層までサポートされているため、セキュリティグループを使って再現可能です。

## EntraIDとオンプレADの連携
EntraIDだけでは、ファイルサーバー、プリンター、GPOなどにアクセス制御をかけることはできないため、オンプレADと連携してアクセス制御を行う方法が3種類存在します。

| 方法                | 管理対象     | Entra IDとの関係                       |
| ----------------- | -------- | ---------------------------------- |
| Hybrid Join       | デバイス     | オンプレADとEntra IDの両方に参加              |
| Entra Kerberos    | ファイル共有など | Entra ID Joinデバイスでもオンプレリソースにアクセス可能 |
| Application Proxy | Webアプリ   | Entra ID認証でオンプレアプリを保護・公開           |

### 1. **ハイブリッドAzure AD Join（Hybrid Join）**
- オンプレADに参加しているデバイスを**Entra IDにも登録**することで、クラウドとオンプレの両方から管理できるようになる。
- これにより、**条件付きアクセスやSSO（シングルサインオン）**が可能になる。

### 2. **Entra Kerberos（旧Azure AD Kerberos）**
- Entra IDに参加しているデバイス（Azure AD Join）でも、**オンプレのファイル共有やプリンターにアクセスできるようにする仕組み**。 
- これは、**KerberosチケットをEntra ID経由で発行**することで実現される。
- つまり、**オンプレADに直接参加していなくても、Entra IDの認証情報でSMB共有などにアクセスできる**ようになる！

### 3. **Entra ID Application Proxy**
- オンプレミスのWebアプリケーションを**クラウド経由で安全に公開**し、Entra IDの認証・条件付きアクセスで保護する。 
- これにより、**オンプレアプリに対してEntra IDベースのSSOやMFAが適用可能**。

### SID、ObjectID
オンプレADはアカウントを一意に管理するためにSIDを使っているけれど、EntraIDではObjectID（GUID）というものを使っています。
オンプレADから同期されたアカウントは、EntraIDで管理する時もObjectIDと紐づけたSIDを持っているけれど、EntraIDで作成されたアカウントはSIDを持っていません。

SIDはオンプレのアクセス制御（ACL）に使用されるので、EntraIDからオンプレのリソースを管理するにはオンプレADとの連携が必要になります。

EntraIDでは、ObjectIDに紐づくフィールドの１つに「onPremisesSecurityIdentifier」があり、オンプレADから同期されたアカウントには元々使用していたSIDが登録されます。

#### Hybrid Azure AD Join での扱われ方
オンプレADに参加しているデバイスをEntraIDにも登録して、連携して管理できるようにします。ユーザーはオンプレADのSIDでログオンして、EntraIDのObjectIDとリンクされます。

#### Entra Kerberos での扱われ方
EntraIDからKerberos TGT（チケット・グラント・チケット）を発行し、TGTにオンプレADのSIDを含めることでEntraIDの認証情報を使ってオンプレリソースにアクセス出来るようにする機能です。

含めるSIDはオンプレADから同期したアカウントなら「onPremisesSecurityIdentifier」に保管しておいたSIDを使用、EntraIDで作成されたアカウントなら（保管しているSIDが無いので）手動で割り当てます。

## プロトコルの違い

| 項目            | Entra ID                                                                                                      | オンプレAD                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **主な認証プロトコル** | **OAuth 2.0**（認可）  <br>**OpenID Connect**（認証）  <br>**SAML 2.0**（主にレガシーSaaS連携）  <br>**WS-Federation**（一部旧式アプリ） | **Kerberos v5**（オンプレADの標準）                                                                                   |
| **認可方式**      | **RBAC（Role-Based Access Control）**  <br>**条件付きアクセス（Conditional Access）**  <br>**ポリシー評価（PIM, CA, MFAなど）**     | SIDベースのACL（アクセス制御リスト）                                                                                        |
| **トークン形式**    | **JWT（JSON Web Token）**  <br>**SAMLアサーション**（SAML利用時）                                                          | Kerberosチケット（TGT, ST）                                                                                        |
| **対象**        | クラウドアプリ（Microsoft 365, Azure, SaaSなど）や一部オンプレアプリ（Application Proxy経由）                                          | オンプレミスのWindowsリソース（ファイル共有、プリンター、SQL Serverなど）                                                                |
| **認証の流れ**     | 1. ユーザーがアプリにアクセス  <br>2. Entra IDが認証（パスワード/MFA/証明書など）  <br>3. アクセストークン/IDトークンを発行  <br>4. アプリがトークンを検証してアクセス許可  | 1. ユーザーがKDCにログオン要求  <br>2. TGT（チケット・グラント・チケット）を取得  <br>3. 対象サービス用のST（サービスチケット）を取得  <br>4. サービスにチケットを提示してアクセス |
### 比較のポイント
| 観点          | Entra ID                         | オンプレAD                                   |
| ----------- | -------------------------------- | ---------------------------------------- |
| **設計思想**    | クラウドネイティブ、インターネット前提              | オンプレミス、LAN前提                             |
| **識別子**     | Object ID（GUID）                  | SID（Security Identifier）                 |
| **認証対象**    | Webアプリ/API/クラウドサービス              | Windowsサービス/SMB/プリンターなど                  |
| **トークンの中身** | クレーム（claims）ベース（例：roles, groups） | SIDとPAC（Privilege Attribute Certificate） |
| **拡張性**     | 多要素認証、条件付きアクセス、デバイス準拠など柔軟        | 拡張は限定的（証明書Kerberosなど）                    |
### ハッシュの使用方法
| 観点              | **Kerberos**          | **OAuth / OpenID Connect**     |
| --------------- | --------------------- | ------------------------------ |
| **ハッシュの目的**     | パスワードの代替鍵（暗号化・復号）     | トークンの署名・検証・整合性チェック             |
| **使われる場面**      | 認証時のチケット取得・復号         | トークン発行・署名・検証                   |
| **主なアルゴリズム**    | NTLMハッシュ、AES、RC4など    | SHA-256、RS256（RSA + SHA-256）など |
| **ネットワーク上の安全性** | パスワードを直接送らず、チケットでやり取り | トークンに署名を付けて改ざん防止               |
