### 2種類のDNSリゾルバー

#### DNSのリゾルバーとは何でしょうか
とても良い質問です。  
**DNSリゾルバー（DNS Resolver）**とは、簡単に言うと「**人間が入力したドメイン名（例：[www.example.com）をIPアドレスに変換するための仲介役](http://www.example.xn--com\)ip-883eubwg6a6qoeudrlvmxi9uv514bfvag82n9i2abfu/)**」です。

---

### 🔍 DNSリゾルバーの基本的な役割

インターネット上の通信は **IPアドレス（例：192.0.2.1）** を使って行われますが、人間には覚えにくいので **ドメイン名（例：[www.google.com）](http://www.google.com\)/)** が使われています。  
この「名前 → IPアドレス」の変換をしてくれる仕組みが **DNS（Domain Name System）** です。

そして、その変換処理をユーザーの代わりに行ってくれるのが **DNSリゾルバー** です。

---

### ⚙️ DNSリゾルバーの動作イメージ

以下のような流れで動作します：

1. **ユーザーがURLを入力**
    
    - 例：「[https://www.google.com」をブラウザに入力。](https://www.google.xn--com-k03botqh2e6e7lqgl236akbd./)
        
2. **OSまたはブラウザがDNSリゾルバーに問い合わせ**
    
    - 「[www.google.comのIPアドレスを教えて」と質問。](http://www.google.xn--comip-7v3d8o4hta8cxzlgnluhmt3129bh88bl32i./)
        
3. **リゾルバーがキャッシュを確認**
    
    - 過去に問い合わせた結果を保存していれば、それを返します。
        
4. **キャッシュになければDNSサーバへ問い合わせ**
    
    - ルートDNS → TLD DNS（.comなど）→ 権威DNS（google.comを管理するサーバ）へと順に問い合わせ。
        
5. **IPアドレスを取得して返す**
    
    - 最終的なIPアドレスをユーザーの端末に返します。
        
6. **通信が開始される**
    
    - ブラウザがそのIPアドレスへHTTPリクエストを送信。
        

---

### 🧠 リゾルバーの種類

|種類|役割|例|
|---|---|---|
|**スタブリゾルバー（Stub Resolver）**|クライアント（PCやスマホ）に内蔵。DNS問い合わせをフルリゾルバーに渡す。|WindowsやmacOSのDNS機能|
|**フルリゾルバー（Recursive Resolver）**|問い合わせをすべて解決してIPを返す。キャッシュも持つ。|ISPのDNS、Google Public DNS (8.8.8.8)、Cloudflare (1.1.1.1)|

---

### 🧩 具体例

たとえば、あなたのPCが「[www.microsoft.com」を開こうとすると：](http://www.microsoft.xn--com:-dy3c4m4c3bwib89atc5187p/)

1. スタブリゾルバー（PC内）が「8.8.8.8」などのフルリゾルバーに問い合わせ。
    
2. フルリゾルバーがインターネットのDNS階層をたどってIPアドレスを探す。
    
3. 結果（例：13.107.42.16）をあなたのPCに返す。
    
4. PCはそのIPに接続してページを表示。
    

---

### 🛠 まとめ

|用語|意味|
|---|---|
|**DNSリゾルバー**|ドメイン名をIPアドレスに変換する仕組みの仲介役|
|**スタブリゾルバー**|端末側で問い合わせを出す軽いリゾルバー|
|**フルリゾルバー（Recursive）**|実際にDNSサーバをたどって結果を取得するリゾルバー|
|**権威DNSサーバ**|実際のドメイン情報を保持しているサーバ|

#### スタブリゾルバーは、エッジに設定したDNSサーバのアイピーを使って、フルリゾルバーに名前解決要求を行うのか？
はい、その通りです。

**スタブリゾルバー**（DNSクライアント）は、通常、**利用者側の機器（エッジ）**で動作する名前解決のクライアント機能です。

このスタブリゾルバーは、名前解決の要求（クエリ）を受け取ると、あらかじめOSなどのネットワーク設定で**「DNSサーバー」として指定されているIPアドレス**（つまり、**フルサービスリゾルバー**や**キャッシュDNSサーバー**のIPアドレス）に向けて、名前解決の要求を送信します。

---

### 💡 スタブリゾルバーとフルサービスリゾルバーの関係

- **スタブリゾルバー（DNSクライアント）**
    
    - Webブラウザなどのアプリケーションから要求を受け取る。
        
    - **設定されているフルサービスリゾルバーのIPアドレス**に、ドメイン名の解決を依頼する（**再帰問い合わせ**）。
        
    - 自分自身では、ルートサーバーなどへの問い合わせ（非再帰検索）は行いません。
        
- **フルサービスリゾルバー（キャッシュDNSサーバー）**
    
    - スタブリゾルバーから要求を受け取る。
        
    - 必要に応じて、ルートDNSサーバーから階層的に問い合わせ（**非再帰検索**や**反復検索**）を行い、IPアドレスを見つけ出す。
        
    - 見つけたIPアドレスをスタブリゾルバーに応答として返す。
        
    - 問い合わせ結果を内部にキャッシュ（保存）して、次回の問い合わせに備える。
        

したがって、スタブリゾルバーは、おっしゃる通り**エッジに設定されたDNSサーバー（フルサービスリゾルバー）のIPアドレス**宛に名前解決要求を送ります。

#### Windows、LinuxそれぞれのOSで、スタブリゾルバにDNSサーバのIPアドレスを設定する方法
スタブリゾルバー（DNSクライアント）にフルサービスリゾルバー（キャッシュDNSサーバー）のIPアドレスを設定する方法は、OSによって異なります。

主に**ネットワークアダプターの設定**または**設定ファイル**を通じて行います。

---

## 💻 1. Windows での設定方法

Windowsでは、通常、GUI（グラフィカルユーザーインターフェース）を使ってネットワークアダプターごとに設定します。

### 手順（Windows 10/11 の場合）

1. **「設定」**を開きます（`Windowsキー` + `I`）。
    
2. **「ネットワークとインターネット」**を選択します。
    
3. 使用している接続タイプに応じて**「イーサネット」**または**「Wi-Fi」**を選択します。
    
4. 接続しているネットワーク名（アダプター）を選択し、**「プロパティ」**を開きます。
    
5. 下の方にある「DNSサーバーの割り当て」の項目の**「編集」**ボタンをクリックします。
    
6. 設定を「自動（DHCP）」から**「手動」**に変更し、**IPv4**をオンにします。
    
7. **「優先DNS」**と**「代替DNS」**の欄に、設定したいフルサービスリゾルバーのIPアドレス（例：`8.8.8.8` や `1.1.1.1` など）を入力します。
    
8. **「保存」**をクリックして完了です。
    

> **💡 コマンドプロンプトでの確認**
> 
> 設定後、コマンドプロンプトで以下のコマンドを実行すると、設定されたDNSサーバーのIPアドレスを確認できます。
> 
> Bash
> 
> ```
> ipconfig /all
> ```

## 🐧 2. Linux での設定方法

Linuxではディストリビューションや利用しているネットワーク管理ツール（NetworkManager、systemd-resolvedなど）によって推奨される方法が異なりますが、最も基本的な設定ファイルは`resolv.conf`です。

### 1. 永続的な設定（推奨される方法）

最近の主要なLinuxディストリビューション（Ubuntu, CentOS, RHELなど）では、NetworkManagerや`systemd-resolved`などのサービスがDNS設定を管理しており、`resolv.conf`を手動で編集すると再起動時などに上書きされる可能性があります。

#### NetworkManager を使用している場合（GUIまたは`nmcli`コマンド）

- GUIで設定：
    
    ネットワーク設定画面（Wi-Fiや有線の設定）を開き、IPv4（またはIPv6）タブ内の**「DNS」**設定を手動に切り替え、IPアドレスを入力します。
    
- nmcliコマンドで設定：
    
    ネットワーク接続名（例: eth0 や Wi-Fi）がわかっている場合、以下のコマンドで設定します。
    
    Bash
    
    ```
    # 自動で取得したDNSを無視する設定
    sudo nmcli connection modify "接続名" ipv4.ignore-auto-dns yes
    # 使用するDNSサーバーのIPアドレスを設定
    sudo nmcli connection modify "接続名" ipv4.dns "8.8.8.8 8.8.4.4"
    # 設定を適用
    sudo nmcli connection up "接続名"
    ```
    

#### `systemd-resolved` を使用している場合

`systemd-resolved`の設定ファイル（`/etc/systemd/resolved.conf`）を編集します。

1. 設定ファイルを開きます。
    
    Bash
    
    ```
    sudo vi /etc/systemd/resolved.conf
    ```
    
2. `[Resolve]`セクションで、`#DNS=`の行のコメントを外し、DNSサーバーのIPアドレスをスペース区切りで記述します。
    
    Ini, TOML
    
    ```
    [Resolve]
    DNS=8.8.8.8 8.8.4.4
    #FallbackDNS=...
    ```
    
3. サービスを再起動して設定を適用します。
    
    Bash
    
    ```
    sudo systemctl restart systemd-resolved
    ```
    

### 2. 伝統的な設定ファイル (`/etc/resolv.conf`)

一時的な変更や、NetworkManagerなどが動作していない環境では、このファイルを直接編集します。

1. 設定ファイルをエディタで開きます。
    
    Bash
    
    ```
    sudo vi /etc/resolv.conf
    ```
    
2. 既存の内容を削除またはコメントアウトし、以下の形式でDNSサーバーのIPアドレスを記述します。
    
    コード スニペット
    
    ```
    # 設定するフルリゾルバーのIPアドレスを記述
    nameserver 8.8.8.8
    nameserver 8.8.4.4
    
    # オプション: ドメイン名の省略時に検索するドメイン
    search example.com
    ```
    
    - **nameserver:** フルリゾルバーのIPアドレスを指定します。複数行記述すると、上から順に問い合わせが行われます。
        

> **注意点:**
> 
> このファイルを直接編集した場合、ネットワークの再起動やDHCPリース更新時などに**自動で上書きされてしまう**ことが多いです。永続的に設定したい場合は、上記「永続的な設定」の方法（NetworkManagerや`systemd-resolved`）を利用してください。

---

ご使用の環境（Windowsのバージョン、Linuxのディストリビューション）によって最適な設定方法は若干異なりますが、基本的には上記の手順でスタブリゾルバーが問い合わせる先のIPアドレスを設定できます。

特定のLinuxディストリビューション（例：Ubuntu 22.04での設定方法）について、より詳しい手順が必要でしたら、お気軽にお申し付けください。

#### インターネットサービスプロバイダーから通知されるDNSサーバのIPアドレスは、フルリゾルバーかキャッシュDNSサーバか？
ご質問の通り、**インターネットサービスプロバイダー (ISP) から通知されるDNSサーバーのIPアドレスは、「フルサービスリゾルバー」**であり、同時に**「キャッシュDNSサーバー」**としての役割も持っています。

この2つの用語は、役割が重複しているため、しばしば同じ意味で使われます。

### 💡 用語の整理とISPのDNSサーバーの役割

|**用語**|**役割**|**ISP提供のDNSサーバーとの関係**|
|---|---|---|
|**フルサービスリゾルバー**|**名前解決の実行役**。スタブリゾルバーから要求を受け取り、ルートサーバーから階層的に問い合わせ（非再帰検索）を行い、IPアドレスを最後まで探し出す機能を持つサーバー。|**ISPのDNSサーバーの機能そのもの**です。|
|**キャッシュDNSサーバー**|**名前解決の結果を一時的に保存（キャッシュ）する機能**を持つサーバー。同じ問い合わせが来た場合に高速に回答し、上位のサーバーへの負荷を減らす。|**ISPのDNSサーバーの機能そのもの**です。|
|**スタブリゾルバー**|**名前解決の依頼役**（クライアント側）。ISPのフルサービスリゾルバーに問い合わせを行う、PCやルーター内の機能。|ISPから提供されたIPアドレスに問い合わせる**利用者側の機能**です。|

### なぜISPが提供するのか？

ISPがこのフルサービスリゾルバー（キャッシュDNSサーバー）を提供する主な理由は以下の通りです。

1. **接続の簡便性:** ユーザーが個別にDNSサーバーを探して設定する手間を省くため、DHCPなどで自動的に設定されます。
    
2. **ネットワークの最適化:** ISPのネットワーク内部にあるため、外部のパブリックDNSサーバーにアクセスするよりも**通信経路が短く、名前解決が速くなる**傾向があります。
    
3. **トラフィックの管理:** ネットワーク全体のDNSトラフィックをコントロールし、安定したサービス提供を維持するためです。
    

まとめると、ISPから通知されるIPアドレスは、ユーザー（スタブリゾルバー）からの要求を受けて、インターネット上のドメイン名を解決する**「フルサービスリゾルバー」**であり、その過程で情報を保存する**「キャッシュDNSサーバー」**として機能します。
