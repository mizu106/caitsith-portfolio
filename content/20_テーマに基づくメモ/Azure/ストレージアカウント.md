# ストレージアカウントの基本的なこと

## ストレージアカウントの種類とストレージサービスの種類
ややこしいのですが、ストレージアカウントの種類には2つの意味があります。一つはアクセス速度に関わる Standard / Premium の種類、もう一つは、BLOB、Files、キュー、テーブルなどのデータの保存方法に関する種類です。
-  [ストレージ アカウントの種類](https://learn.microsoft.com/ja-jp/azure/storage/common/storage-account-overview)

組み合わせると以下の様になります。

| ストレージアカウントの種類     | ストレージサービスの種類                                                                        | 選択可能な<br>冗長オプション                                     |
| ----------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Standard 汎用 v2    | ・Azure Blob Storage<br>・Azure Queue Storage<br>・Azure Table Storage<br>・Azure Files | ・LRS<br>・ZRS<br>・GRS<br>・GZRS<br>・RA-GRS<br>・RA-GZRS |
| Premium ブロック BLOB | Blob Storage                                                                        | ・LRS<br>・ZRS                                         |
| SSD ファイル共有        | Azure Files                                                                         | ・LRS<br>・ZRS                                         |
| Premium ページ BLOB  | ページ BLOB のみ                                                                         | ・LRS                                                 |

## アクセス制御
ストレージアカウントのアクセス権を管理する主要な方法として以下のものがあります。
### 共有キー（アクセスキー）
512ビットの文字列で、これを使用すると誰でもストレージアカウントの管理者アクセス権を得ることが出来ます。通常アクセスキーを直書きせず、KeyVaultに格納してローテーションすることでセキュリティを確保します。
### 共有アクセス署名（SAS）
SAS:Shared Access Signature を生成すると、有効期限がある一時的なアクセス権を含むURLを作ることが出来ます。
### EntraID（RBAC）
ユーザーアカウントにRBACを適用して認証することで、詳細なアクセセス制御が可能になります。RBACはコンテナーやストレージアカウント単位で設定可能です。
### パブリックアクセス
URLを使用して匿名でアクセスすることを可能にします。コンテナー単位でアクセス可否を設定可能です。

| サービス            | 共有キー | SAS | EntraID | オンプレAD | パブリックアクセス |
| --------------- | ---- | --- | ------- | ------ | --------- |
| BLOB            | ○    | ○   | ○       | ✕      | ○         |
| AzureFiles（SMB） | ○    | ✕   | ○       | ○      | ✕         |
| キュー             | ○    | ○   | ○       | ✕      | ✕         |
| テーブル            | ○    | ○   | ○       | ✕      | ✕         |

## 暗号化
ストレージアカウントの暗号化には2種類あります。インフラストラクチャーの暗号化と、ストレージアカウントの暗号化の2種類です。
[Azure Storageの静止データ暗号化](https://learn.microsoft.com/ja-jp/azure/storage/common/storage-service-encryption)より
### インフラストラクチャーの暗号化
特に高いレベルでセキュリティを確保する必要がある場合は、インフラストラクチャーレベルでも256ビットAES暗号化を有効にすることでより2重に暗号化して安全を確保できます。
### ストレージアカウントの暗号化
ストレージサービスへのアクセス時に暗号化/復号化で使用する暗号化キーには、Microsoftのマネージドキーとカスタマーマネージドキーの2種類があります。
[Azure Storage の暗号化のためのカスタマー マネージド キー](https://learn.microsoft.com/ja-jp/azure/storage/common/customer-managed-keys-overview)より

| 暗号化キーの種類            | サポートされる<br>ストレージアカウント                      | キーのローテーション   |
| ------------------- | ------------------------------------------ | ------------ |
| Microsoft のマネージド キー | All                                        | Microsoftが担当 |
| カスタマー マネージド キー      | 汎用v2<br>フロックBLOB<br>ページBLOB<br>Azure Files | カスタマーが担当     |
### 暗号化キーの管理方法
暗号化キーは Azure Key Vault または、マネージドHSM（専用ハードウェア）を使用して管理、保護する事が可能です。

## ストレージアカウントのレプリケーション
ストレージアカウントは自動的にレプリケーションを行ってデータ保護を行います。選択可能なレプリケーションの種類は、ストレージサービスの種類で決まっています。また、ストレージアカウント作成後も変更可能ですが、[いくつかの制限](https://learn.microsoft.com/ja-jp/azure/storage/common/redundancy-migration?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json&tabs=portal#limitations-for-changing-replication-types)があり、[ダウンタイムが必要な場合](https://learn.microsoft.com/ja-jp/azure/storage/common/redundancy-migration?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json&tabs=portal#downtime-requirements)もあります。

## エンドポイント
ストレージアカウントのファイルにアクセスするとき使用するエンドポイントは、用途によって複数の種類があります。
エンドポイントには、ストレージアカウントの名前とサービスの名前を含む固定ドメインを組み合わせたURLを使用してアクセスします。
- [標準エンドポイント](https://learn.microsoft.com/ja-jp/azure/storage/common/storage-account-overview#standard-endpoints)

パブリックエンドポイントの使用を許可すると、ストレージアカウントの名前を使用したURLから、匿名（認証無し）でアクセスすることが出来ます。
- [パブリックエンドポイント](https://learn.microsoft.com/ja-jp/azure/storage/common/storage-network-security-set-default-access?toc=%2Fazure%2Fstorage%2Fblobs%2Ftoc.json&bc=%2Fazure%2Fstorage%2Fblobs%2Fbreadcrumb%2Ftoc.json&tabs=azure-portal)

プライベートエンドポイントを使用すると、プライベートリンクを経由することでインターネットに出ずに安全にアクセスすることが出来ます。
- [Azure Storageにプライベート エンドポイントを使用する](https://learn.microsoft.com/ja-jp/azure/storage/common/storage-private-endpoints)
